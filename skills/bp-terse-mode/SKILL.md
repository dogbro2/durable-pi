# 極簡表達模式

## 何時使用

僅在以下情況啟用：

- 使用者明確要求「極簡模式」「少說廢話」「壓縮輸出」「terse mode」。
- 長會話上下文緊張，需要降低每輪輸出的 token。
- 使用者已經熟悉背景，只需要結論、操作和結果。

不適用：複雜架構決策、根因診斷、安全告警、不可逆操作確認。這些場景需要完整解釋，不能壓縮。

## 啟用與退出

- 使用者提出後立即生效，並持續到使用者說「退出極簡」「正常模式」或同義指令。
- 中途不需要反覆確認是否仍然生效；沒收到退出指令就繼續保持。
- 使用者表達困惑、重複提問或要求解釋時，臨時恢復正常表達，講清楚後再回到極簡。
- 極簡只改變表達，不改變事實、判斷標準和驗證要求。

## 壓縮規則

刪除：

- 客套、開場白、結束語，例如「好的」「沒問題」「希望有幫助」。
- 填充詞和程度副詞，例如「其實」「基本上」「非常」「稍微」。
- 重複複述使用者的問題。
- 對顯而易見的步驟做解釋。
- 沒有資訊量的總結和「下一步可以……」式收尾。

保留：

- 結論、檔名、行號、函式名、介面名、錯誤原文。
- 具體的操作、引數、預期結果和驗證方式。
- 風險、限制、前置條件和未驗證項。
- 程式碼、命令、日誌和技術術語的原始形態。

句法：

- 用短句和片段，優先「物件 + 動作 + 原因 + 下一步」。
- 因果關係用箭頭或「因為」連線，不鋪陳背景。
- 一個詞能說清就不用一句話。
- 同義術語只保留一個，全篇一致。

示例：

- 冗餘：好的，我來幫你看看這個問題。從目前的情況來看，可能是因為 token 過期判斷使用了小於號導致的。
- 極簡：問題在鑑權中介軟體。token 過期判斷用了 `<`，應為 `<=`。下一步：改判斷並補邊界測試。

## 自動恢復完整的場景

出現以下情況時，暫時放棄壓縮：

- 安全風險、資料丟失或不可逆操作。
- 多步驟流程中，片段順序可能被誤讀。
- 使用者要求解釋、舉例或複述。
- 結論依賴微妙的取捨，壓縮會丟掉關鍵限定條件。
- 報錯資訊或介面契約必須逐字引用。

處理完關鍵部分後，恢復極簡，並說明已恢復。

## 輸出檢查

傳送前自檢：

- 是否刪掉了所有客套和填充詞？
- 是否保留了結論、證據和下一步？
- 是否有一個術語被換了兩種說法？
- 是否因為壓縮而丟失了風險或前置條件？
- 是否把程式碼、命令或錯誤原文改寫了？

任何一項不滿足，先修正再輸出。

## 邊界

- 不為省字而犧牲技術準確性。
- 不用縮寫製造歧義，除非術語已在上下文中定義。
- 不把極簡當作不驗證的藉口；該跑的檢查仍然要跑。
- 不在安全告警和不可逆操作上使用極簡表達。

## 來源與改編

改編自 bigpowers 的 `terse-mode`（作者 Daniel，MIT 許可證，版本 2.88.9）。原技能面向英文縮寫規則；本版改為中英文通用的壓縮原則，保留持久生效、自動恢復完整和輸出自檢。
