# 程式碼評審清單

## 何時使用

出現以下任一情況時使用本技能：

- 使用者給出 diff、PR 描述或程式碼片段，要求評審。
- 需要在合併前做一次系統性風險檢查。
- 使用者要求把評審意見按阻塞程度排序。
- 需要檢查改動是否破壞既有介面或資料。

不適用：代替使用者執行完整測試、對沒有上下文的大段程式碼做風格挑刺、或把個人偏好寫成阻塞項。

## 輸入

必需：

- 變更內容：diff、PR 連結或改動後的檔案。
- 變更目的：修復什麼問題、實現什麼需求。

可選：

- 相關呼叫方、介面文件、資料模型。
- 測試結果和復現步驟。
- 目標分支和相容性要求。
- 團隊規範或已有程式碼風格。

缺少變更目的時，先要求一句話說明；仍無法確認時，把假設寫在評審開頭。

## 評審順序

按風險從高到低檢查，不要從命名和格式開始：

1. **正確性**：輸入、輸出、狀態轉換是否符合目的。
2. **邊界與錯誤**：空值、零值、超長、超時、重試、部分失敗。
3. **併發與順序**：共享狀態、競態、重複提交、冪等。
4. **資料與相容**：遷移、回滾、舊資料、介面欄位變化。
5. **安全**：鑑權、越權、注入、敏感資訊、日誌洩露。
6. **效能**：額外請求、全表掃描、無界迴圈、記憶體增長。
7. **測試**：是否覆蓋新行為、邊界和失敗路徑。
8. **可維護性**：命名、分層、重複邏輯、死程式碼。

## 工作流程

1. **讀目的**：用一句話複述這次改動要解決的問題。複述不出就停下來問。
2. **劃範圍**：列出改動檔案和受影響呼叫方，標出不在 diff 裡但會被影響的模組。
3. **走主路徑**：按正常輸入推演一遍，確認輸出符合目的。
4. **走失敗路徑**：逐個檢查空值、異常、超時、重試和回滾。
5. **查契約**：確認函式簽名、介面欄位、資料庫列和錯誤碼是否向後相容。
6. **查測試**：確認測試能覆蓋新增分支，且不是隻驗證「不報錯」。
7. **寫意見**：每條給出位置、問題、影響、建議；按嚴重程度排序。
8. **複核**：刪掉純風格偏好，合併重複意見，確認沒有編造行號。

## 嚴重程度

- **Blocker**：會導致資料錯誤、安全問題、線上故障或契約破壞，必須合併前修。
- **Major**：在常見場景下會產生錯誤行為或明顯維護風險，應合併前修。
- **Minor**：邊界場景或可維護性問題，可排期修。
- **Nit**：命名、格式、註釋等偏好，不阻塞合併。
- **Question**：需要作者解釋，不預設對錯。

## 輸出格式

```markdown
# 程式碼評審：<PR 標題或變更摘要>

## 結論

<可合併 / 修復後合併 / 需要重新設計>。一句話說明主要原因。

## 阻塞問題

### [Blocker] <問題標題>

- 位置：`<檔案>:<行號或函式名>`
- 問題：<具體行為，不寫「可能有問題」。>
- 影響：<什麼場景會出錯，後果是什麼。>
- 建議：<最小修複方向，必要時給虛擬碼。>

## 重要問題

### [Major] <問題標題>

- 位置：`<檔案>:<行號或函式名>`
- 問題：<...>
- 影響：<...>
- 建議：<...>

## 次要問題

- **[Minor]** `<位置>`：<問題>；建議 <修改>。
- **[Nit]** `<位置>`：<問題>；建議 <修改>。

## 測試缺口

- <缺失的測試場景>：<為什麼重要>；建議補 <用例>。

## 做得好的地方

- <具體說明一處值得保留的設計或實現。>

## 待確認

- <需要作者回答的問題，附上你的假設。>
```

## 檢查清單

### 正確性

- [ ] 正常輸入得到預期輸出。
- [ ] 條件分支覆蓋了所有列舉值。
- [ ] 迴圈有明確終止條件。
- [ ] 狀態轉換沒有遺漏或非法跳轉。
- [ ] 時間、時區、金額、精度處理一致。

### 邊界與錯誤

- [ ] 空陣列、空字串、零值和缺失欄位有定義。
- [ ] 超長輸入、分頁邊界和最大數量有限制。
- [ ] 外部呼叫失敗會返回可理解的錯誤。
- [ ] 重試不會造成重複寫入。
- [ ] 部分成功時有清理或補償。

### 併發與資料

- [ ] 共享狀態有同步或序列化保證。
- [ ] 同一請求重複執行結果一致。
- [ ] 資料庫遷移可回滾，舊資料可讀。
- [ ] 刪除或重新命名欄位保留了相容期。
- [ ] 事務邊界覆蓋了相關寫入。

### 安全

- [ ] 每個入口都校驗身份和許可權。
- [ ] 使用者輸入不會直接拼進查詢或命令。
- [ ] 錯誤資訊不洩露金鑰、路徑或內部細節。
- [ ] 日誌不記錄完整憑證和個人敏感資訊。
- [ ] 外部 URL 有協議和主機校驗。

### 效能與測試

- [ ] 沒有在迴圈裡發起無界網路或資料庫呼叫。
- [ ] 新增查詢有合適索引或數量上限。
- [ ] 測試覆蓋新增行為，而不只是「不拋錯」。
- [ ] 失敗路徑有測試。
- [ ] 測試不依賴執行順序或真實外部服務。

## 寫評審意見的規則

- 先給結論，再給證據；不要用「感覺」「可能」代替具體場景。
- 每條意見只對應一個問題，避免一條裡塞五個建議。
- 引用程式碼時只引用 diff 中真實存在的片段。
- 對不確定的判斷標成 Question，並寫出你的假設。
- 不要求作者重寫整個模組，優先給最小可行修復。
- 不把格式化、命名偏好升級為 Blocker。
- 同一問題出現多次時，在第一條寫全，其餘標「同上」。

## 邊界

- 不代替作者執行測試或部署。
- 不評審與本次目的無關的歷史程式碼，除非它直接放大本次風險。
- 不對作者能力做評價，只討論程式碼和行為。
- 涉及安全漏洞時，不在公開評論裡貼可利用細節，提示私下同步。
